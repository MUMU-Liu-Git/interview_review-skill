# 数据架构 · interview-bank.json

单一数据源。所有题库 + 复盘 + 真题索引都在这一个文件里（skill 的 `assets/interview-bank.json`）。页面不再有分散的 JS 字面量——数据由 `sync-bank.js` 注入 `interview-practice.html` 的 `<script type="application/json" id="bankData">` 块。页面双击即可打开（数据内嵌，不依赖本地 server）。

## 结构

```jsonc
{
  "updated": "2026-10-03",            // 每次改动后更新为当天

  "dims": [                           // 维度元信息（框架层，一般不动）
    { "id": "D1", "title": "归属与权责", "tag": "L1 事实", "desc": "…" }
    // D1–D11，详见“维度速查”
  ],

  "questions": [                      // 题库（模拟面试问题集的数据源）
    {
      "id": 1,                        // 全局唯一整数，新题 = 现有最大 id + 1
      "dim": "D1",                    // 所属维度 id
      "star": 3,                      // 3=高频 2=较可能 1=深挖（真题也给个 star，一般 3）
      "text": "自我介绍。（**示例公司原题**｜【稳】…）",
      "real": true                    // 真题=true（题干通常也含“原题”二字）
    }
  ],

  "reviews": [                        // 实战复盘卡（数组顺序=页面显示顺序，新卡插到最前=置顶）
    {
      "id": "demo",                   // 英文短 id，用作锚点 #demo（公司英文名/拼音，唯一）
      "title": "示例公司 · AI 产品经理一面 · 实战复盘",
      "tag": "复盘 示例",
      "date": "示例",
      "hl": "green",                  // green/orange/red，按本场整体表现
      "nav": "示例公司一面复盘",       // 侧栏链接文字（前面自动加 ★）
      "md": "> 复盘对象：…完整 Markdown…"
    }
  ],

  "realIndex": [                      // 真题索引（公司 → 维度 → 真题），页面顶部“🎯 真题索引”
    {
      "co": "示例公司 · AI 产品经理一面",
      "key": "示例公司",              // 必填：公司关键词，本块引用的每道题题干里都必须含它
      "rid": "demo",                  // 有复盘卡时必填：对应 reviews[].id，正文 Qn 须与本块题号完全一致
      "date": "示例",
      "n": "一句话场次小结（火力分布 + 最大扣分）",
      "dims": [
        { "d": "D5", "t": "产品定义与价值", "items": [
          { "id": 7, "t": "这个产品的目标用户到底是谁？", "f": "亮" }
        ]}
      ]
    }
  ]
}
```

## 关键约束
- `questions[].id` 全局唯一。新题号 = 当前所有题目 id 的最大值 + 1，依次递增。
- `questions[].dim` 必须是 `dims` 里存在的 id。
- `realIndex[].items[].id` 必须引用已存在的**真题**（`real:true`），且 `d` 与该题 `dim` 一致、题干含本块 `key`。
- **复用旧题号的红线**：只有"同一道题、问法基本一致"才复用。复用时必须把旧题 `real` 置 true，并在题干末尾括号里追加 `**公司原题**｜【flag】点评`。问法/前提不同（如"为什么做产品"vs"专业更适合算法为什么做产品"）一律新建题号。
- 复盘卡正文里写的"对应题库 **Qn**"必须与该场 realIndex 块题号一一对应，不多不少。
- `reviews[].id` 唯一，只用小写英文/拼音（做 HTML 锚点）。
- 真题判定与排序交给页面：真题（`real:true` 或题干含“原题”）> 高频(3) > 较可能(2) > 深挖(1)，同级保持录入顺序。**只管 append，不要手动排序。**
- 校验/注入统一走 `scripts/sync-bank.js`，它会检查题号唯一、维度合法、复盘卡字段完整、注入后 JSON 仍可解析，以及上面三条真题对齐规则（不通过直接拒绝写入）。
